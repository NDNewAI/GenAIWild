Big idea 1 · built from the bottom up

The layers of a computer

You (and agents)

Act through programs. Claude is one of them.

Programs

Word, Chrome, Obsidian, Terminal: open and save files.

Files

Named bundles of data: syllabus.docx, photo.png

Directories (folders)

A tree of folders. A file's address is its path.

Operating system

macOS, Windows: keeps the tree, runs programs, sets access.

Hardware

Processor, memory, and the drive that stores the bytes.

Most apps hide the two middle layers. Today we look at them directly.

Build it from the bottom: hardware, then the operating system, and so on up to you. Before each click, ask what sits on top of what's showing. The stack is the picture to remember: you reach your files through programs, and the operating system sits under all of them. Then the Terminal demo, which shows the two hidden layers plainly: open Terminal (Mac: Applications, Utilities; Windows: PowerShell); pwd shows where you are, ls lists what's here, ls -a shows hidden files too, cd Documents moves you.

A folder holds files and other folders. That nesting makes a tree.

Follow the gold route from the top. Written out, that route is the file's path:

/Users/you/Documents/GAIW/syllabus.docx

Windows: C:\Users\you\Documents\GAIW\syllabus.docx

Trace the gold route with your finger or cursor, one folder at a time, while reading the path aloud: each slash is one step down the tree. "Where did my file go?" is almost always a path question. Terminal demo: pwd, cd Documents, ls, cd .. to go back up. The extension (.docx) tells programs which format to expect.

Big idea 7 · a feedback loop

Outputs become inputs

Claude writes a note today. Tomorrow's run reads it.

What a system produces shapes what it does next.

"Every output is a potential input."

Input

Process

Output

the output becomes the next input

This is the only place the deck uses "loop": an output comes back around as an input. Adapted from the Spring 6B line "every output is a potential instruction." Ask: what could go wrong if a mistake in today's output becomes tomorrow's input? That's why the database keeps the original sources untouched in raw/.

Big idea 8 · since Week 1

Generative and deterministic, together

Generative

A language model drafts and proposes. Flexible, but it varies run to run.

Deterministic

An ordinary program counts and checks. Same input, same output.

Prompt

Many possible outputs

Run it again: a different path.

Input

Fixed steps

Same output

Run it again: the identical result.

Left: one prompt can branch into many possible outputs, which is why generative output varies. Right: a fixed sequence of steps gives the same result every run. Use each where it's strong, and let one check the other. Example from earlier: grep is deterministic; asking Claude "which of these files are about evaluation?" is generative.

Big idea 9

Automation is a trigger, a script and a log

Trigger

7am, or a new file arrives

Script

A fixed list of steps, nobody watching

Log

One line per run

log.md

Mon 7:00 ran · 3 new notes

Tue 7:00 ran · 2 new notes

Wed 7:00 (no line)

Thu 7:00 ran · 4 new notes

Wednesday's run failed, and nothing announced it. A missing line is the only alarm.

Ask before revealing the right-hand sentence: what does the gap on Wednesday tell you? Everyday examples of trigger, script and log: a thermostat schedule, an email filter, a bank's nightly batch. We say script, not loop: a script is a fixed list of steps run in order. Save "loop" for feedback loops, where an output comes back as an input (Big idea 7). The new part is that one step in the script can now be a language model.

About the name

The internet calls this a "second brain." We don't.

A folder of files doesn't remember, understand, or care whether anything in it is true.

It stores text. A program rearranges that text when something triggers it.

Question

What does "second brain" lead you to expect that this folder can't do?

We name the metaphor so we can examine it, the same way we flag anthropomorphism in the tutorials and posts you'll read. Take two or three answers. Then: what the folder actually has is files, links, a log, and one folder only you write in.

Step 1, continued

Who: Claude or you

Where: Code tab

What you'll see, and the by-hand way

What you'll see

Claude tells you its plan, then stops before every command and asks permission. Read its explanation, then choose Allow. Windows may ask "Do you want to allow this app to make changes?" Choose Yes. The first time Obsidian opens, a Mac may say it was downloaded from the internet. Choose Open.

If the install doesn't work

  1. Go to obsidian.md and click Download. The site picks Mac or Windows for you.
  2. Mac: open the downloaded .dmg file, drag the Obsidian icon onto the Applications folder, then eject the disk image. Windows: run the downloaded .exe and accept the defaults.
  3. Open Obsidian from Applications (Mac) or the Start menu (Windows). Choose Open if your computer asks whether you're sure.
  4. Make an empty folder called GAIW Research Database in your Documents folder.
Permission prompts are the safety feature, not an error. If Claude can't finish the install for any reason, the right-hand steps get the same result; then continue at step 2.
